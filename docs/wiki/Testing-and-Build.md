# Testing and Build

## Local quality gate

Run this sequence before pushing or creating a release:

```powershell
uv lock --check
uv run ruff check .
uv run mypy
uv run pre-commit run --all-files
uv run pytest -q --cov=station_calibration --cov-report=term-missing
uv build
```

`uv build` is only required for release candidates, but running it before a tag
catches packaging problems early. The sections below describe each check.

## Tests

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

The suite currently collects **237 tests** when the optional Ice package is
installed. Without `zeroc-ice`, `test_ice_adapter.py` is skipped. The tests run
without network access.

`pytest` is configured in `pyproject.toml` with `testpaths = ["tests"]` and
`pythonpath = ["src"]`.

Run the suite with branch coverage and a per-file missing-line report:

```powershell
uv run pytest -q --cov=station_calibration --cov-report=term-missing
```

Coverage omits the optional Ice transport and generated Ice stubs, and currently
enforces a `90%` floor. Ice behavior is exercised separately by the `test-ice`
job because `zeroc-ice` is an optional dependency. The generated `coverage.xml`
is published by CI as an artifact.

## Linting and formatting

Ruff is configured in `pyproject.toml` and excludes the generated Ice stubs:

```powershell
uv run ruff check .
uv run ruff check --fix .
```

The formatter uses the existing 120-character line length and preserves the
current quote style. A repository-wide formatting pass is intentionally deferred
so that this baseline stays reviewable. Until that pass lands, format touched
files directly or through the manual pre-commit hook:

```powershell
uv run ruff format path\to\file.py
uv run pre-commit run ruff-format --hook-stage manual
```

## Static type checking

`mypy` is configured in `pyproject.toml` for the `src/station_calibration`
package. The generated Ice stubs are excluded, and third-party imports without
stubs are ignored during this first stage. Untyped function bodies are checked,
but the stricter `disallow_untyped_defs` family is intentionally deferred until
the remaining modules are annotated:

```powershell
uv run mypy
```

## Pre-commit

Install the hooks once per checkout:

```powershell
uv run pre-commit install
```

On each commit, pre-commit runs `ruff check --fix`, TOML/YAML validation,
trailing-whitespace cleanup, end-of-file fixing, and large-file checks. Generated
Ice stubs and the shared `ice/` Slice contracts are excluded. Run the hooks
manually with:

```powershell
uv run pre-commit run
```

## Lock file

```powershell
uv lock --check
```

Verifies that `uv.lock` matches `pyproject.toml`. The repository currently locks
68 packages.

> The project version is generated from Git, so it is not stored in `uv.lock`.
> Run `uv lock` when dependencies or build requirements change; version changes
> alone do not require a lockfile update.

## Build

```powershell
uv build
```

Hatchling produces:

```text
dist/3dstationcalibration-<version>-py3-none-any.whl
dist/3dstationcalibration-<version>.tar.gz
```

`<version>` is generated by `hatch-vcs`; see [Versioning](#versioning).

### Wheel contents

- the `station_calibration` package, including `resources/config.toml` and the
  PEP 561 `py.typed` marker;
- the Ice adapter, server, client, and generated stubs;
- `LICENSE` and `THIRD_PARTY_NOTICES.md` as license files.

ZeroC Ice is **not** bundled; it remains an optional extra.

### sdist contents

```text
src/station_calibration
scripts/generate_ice_stubs.py
tests
ice                  # production contracts; legacy *_test.ice files are excluded
deploy
docs
README.md
CHANGELOG.md
LICENSE
THIRD_PARTY_NOTICES.md
pyproject.toml
```

The Ice stub generator is shipped in the sdist so an unpacked source archive can
regenerate stubs from the bundled contracts. The release and CI helpers in
`scripts/` are not shipped; the release helper needs a Git checkout, which an
unpacked sdist does not provide.

## Continuous integration

`.gitlab-ci.yml` runs on every push:

- **test** — `uv sync --frozen`, `uv lock --check`, and `pytest` with branch
  coverage, publishing `coverage.xml` as an artifact;
- **lint** — `uv sync --frozen`, `ruff check .`, and `mypy`;
- **test-ice** — installs ZeroC Ice from the official Debian repository and runs
  `tests/test_ice_adapter.py` with the system Python;
- **build** — `uv build`, then install the wheel into the test environment,
  verify the packaged `py.typed` marker, and check `3dsc --version` and
  `3dsc-ice-server --version`;
- **check** — `bash -n deploy/linux/3dsc-update`, compile the maintainer
  scripts, and parse both Windows PowerShell scripts with
  `scripts/check-powershell.ps1`.

The build job publishes `dist/` as an artifact for one week.

## Versioning

The package version is generated automatically by `hatch-vcs` from Git tags. It
is not written in `pyproject.toml`. Tags use calendar versioning in the form
`vYYYY.MM.DD.N`, for example `v2026.11.02.0`. `N` starts at `0` for the first
release of a day and increments for each further release that day.

Always include the revision suffix in new tags. Legacy tags without it (for
example `v2026.10.25`) are treated as revision `0` by the release helper and the
automatic updaters.

A build from a tagged commit receives that release version. PEP 440 drops leading
zeros, so tag `v2026.11.02.0` reports `2026.11.2.0`; this is the same release.
Commits after the last tag receive an automatically generated development
version, for example `2026.11.2.1.dev4`. This means every build is traceable
without editing a version string by hand.

Check the installed version:

```powershell
python -c "import station_calibration; print(station_calibration.__version__)"
3dsc-ice-server --version
3dsc-ice-client --version
3dsc --version
```

### Create a release

Run the [local quality gate](#local-quality-gate) and confirm the GitLab
pipeline is green before tagging. Use the release helper from a clean checkout.
It fetches tags, refuses a dirty working tree or an unpushed commit, and creates
an annotated tag:

```powershell
.\.venv\Scripts\python.exe scripts\release.py --dry-run
.\.venv\Scripts\python.exe scripts\release.py --run-tests
```

The helper:

1. refuses to run when `git status --porcelain` is not empty;
2. fetches tags from `origin`;
3. refuses a detached HEAD or a commit that is not pushed to the branch upstream;
4. selects the next `.N` for today (or for `--date YYYY.MM.DD`);
5. creates the annotated tag and pushes it.

Useful options:

| Option | Effect |
| --- | --- |
| `--no-push` | Create the tag locally without pushing it |
| `--date YYYY.MM.DD` | Use a date other than today |
| `--message "..."` | Set the annotated tag message |
| `--sign` | Create a GPG-signed tag (`git tag -s`) |
| `--run-tests` | Run `python -m pytest -q` first |
| `--allow-unpushed` | Skip the upstream check |
| `--allow-tagged-head` | Allow a second release tag on the same commit |

The manual equivalent is:

```powershell
git status --porcelain          # must print nothing
git push
git tag -a v2026.11.02.0 -m "Release v2026.11.02.0"
git push origin v2026.11.02.0
uv build
```

Use `git tag -s` (or `--sign`) instead of `-a` when a GPG key is configured. The
automatic updaters can verify signatures; see
[Deployment](Deployment#update-policy).

> **Never move or reuse a deployed release tag.** The automatic updater selects
> tags by name and rolls back to the previous tag. If a release is faulty, fix
> it and publish the next `.N`; do not rewrite history or force-push a tag.

If a source archive is built without Git metadata, `hatch-vcs` falls back to the
version stored in the sdist metadata, or to `0.0.0` when no metadata is present.
Shallow CI clones must fetch tags (`git fetch --tags --unshallow` or
`fetch-depth: 0`), otherwise the tag history is unavailable.
